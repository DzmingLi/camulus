#+title: Camulus 代码结构与总体设计

Camulus 提供统一的内容模型、时间线、回复树、已读状态和收藏归档。后端负责来源协议及订阅语义，共享模块负责内容状态，Emacs 界面负责呈现和交互。OCaml 的模块系统描述能力边界，Eio 负责可取消的并发任务，Ecaml 将程序接入 Emacs。

界面、配置和宿主操作通过 Ecaml 接入 Emacs。公共模块位于 =src/=，各来源的协议与命令注册位于 =src/backends/=。本文按现有代码解释模块职责、请求流转和并发边界。

* 开发构建
在仓库根目录运行 =nix develop -c dune build src/camulus_native.so= 构建原生模块。产物位于 =_build/default/src/=。

运行 =nix build .#emacs-camulus= 构建 ELPA 包。Nix 使用 opam-nix 构建 OCaml 依赖，并应用 Ecaml / Eio 的宿主适配补丁。

flake 按目标平台分别生成依赖和原生模块。=mkEmacsPackage= 通过传入的 Emacs 包集确定目标。opam-nix 在求值时运行依赖解析器，跨平台构建需配置目标平台的 Nix builder。Linux 包引入 WebKitGTK，macOS 包默认使用外部浏览器播放正文视频。

* 阅读源码的顺序
建议先读 [[../src/content.ml][content.ml]]，理解列表和正文交换哪些数据；再读 [[../src/backend.ml][backend.ml]]，理解必需接口与可选能力。接着用一个实际请求串起 [[../src/reader_ui.ml][reader_ui.ml]]、[[../src/runtime_ui.ml][runtime_ui.ml]]、[[../src/protocol.ml][protocol.ml]] 和 [[../src/runtime.ml][runtime.ml]]。最后查看某个后端及 [[../src/content_state.ml][content_state.ml]]。

不要先从 =camulus_native.ml= 的命令定义逐行读起。它是装配入口，理解各模块的职责后，里面的大部分注册调用才容易解释。

* 公共抽象
** 后端、组与订阅源
- *后端（backend）* 接入一种协议、服务或内容格式。基础接口提供组内分页读取。讨论串读取、订阅设置和互动等能力可以分别提供。
- *组（group）* 是后端提供的按需浏览入口。后端定义组的定位方式，例如服务实例和组名。注册后可从组目录进入，打开条目时按需获取正文。
- *订阅源（subscription source）* 是为个人收件箱提供更新的入口。它可以引用某个组，也可以来自其他后端提供的活动流。公共同步通过 =followed= 发现订阅源。

订阅设置（subscription policy）描述订阅目标和接收规则。=Backend.Subscription= 是读取和修改规则的可选能力，=Topic_tracking= 还可以枚举后端管理的讨论串追踪设置。

** 内容与阅读
- *消息（message）* 是可独立识别的一条内容，例如独立文章、讨论串首帖或某条回复。=Content.message= 也用于列表，列表批次可以只提供元数据。
- *独立文章（standalone article）* 是按单条消息阅读的内容。收藏类型 =Article= 同样可以指向讨论串中的某一条消息。
- *讨论串（thread）* 是由首帖和各级回复组成的阅读单位。一个尚无回复的讨论串只包含首帖。后端可提供服务的原生讨论串 ID，Camulus 也可以按回复和引用关系推导哪些消息属于同一讨论串。
- *回复树（reply tree）* 是讨论串内消息按父子关系排列的阅读结构。分支是从某一楼开始的子树，包含该楼及其各级回复。父消息缺失时，已有回复仍可显示。=Content.thread_batch= 是渐进加载时传递消息、缺口和完成状态的批次。
- *活动（activity）* 是同一条消息上可单独处理的一次变化，例如正文修订或新的互动事件。后端可用 =activity= 提供稳定的去重标识。=created= 提供来源时间，本地活动序号用于记录已处理的范围。
- *列表条目（summary row）* 是浏览列表或时间线中可以打开的一行。它可以代表一条消息，也可以代表按讨论串合并后的多条消息。

** 收件箱与本地状态
- *收件箱（inbox）* 是订阅内容的本地集合。收件箱视图（inbox view）将选中的订阅源合并成可处理的列表。完整正文的同步边界及实现进度见 [[*订阅同步与组浏览][订阅同步与组浏览]]。
- *已读与移除（read / dismiss）* 分别记录单条消息的阅读状态和列表中已处理的活动范围。两种状态可以独立更新。
- *收藏（favorite）* 是文件夹与一条消息或整个讨论串的归属关系。同一目标可归属多个文件夹。
- *正文缓存与归档（cache / archive）* 都保存本地正文，归档还保存离线阅读所需的资源。收藏关系和正文数据分别存储。

** Thread 的命名
公共代码用 =thread= 表示整个讨论串。=Threading= 是读取讨论串的可选后端接口，=Content.message.thread_id= 是后端传入的可选讨论串标识，=thread_batch.thread= 是当前读取的目标标识。公共存储推导出的 =conversation_id= 用于合并列表行，可能随回复关系补齐而变化。

物理上同在 =src/=，不意味着所有模块都依赖 Emacs。[[../src/dune][src/dune]] 定义了三个主要编译单元：

| 编译单元               | 内容                                             | 是否依赖 Ecaml |

后端目录可以同时包含协议库和 Emacs 适配库。协议库处理网络和内容转换，适配库注册命令、快捷键及 worker。模块能否脱离 Emacs 运行由 Dune 的库依赖决定。

* 后端模块与运行时注册
** 模块签名描述后端能做什么
[[../src/backend.ml][backend.ml]] 中的 =module type S= 是一个 OCaml 模块签名。实现它的模块需要提供自己的会话类型 =t=、组类型 =group=、游标类型 =cursor=，以及列表操作。这里的 =S= 是签名名称，并不代表一个后台线程或服务实例。

后端用抽象类型定义各自的组标识和分页游标。公共界面把它们转成字符串，用于配置和请求传递。

=Threading=、=Voting=、=Liking=、=Subscription= 和 =Topic_tracking= 是独立的可选签名。后端可以按能力实现这些接口，并为订阅选择自己的 =target= 和 =settings= 类型。

基础签名用 =val list= 声明组内分页读取。后端在接入运行时的时候注册自己的标识。声明签名本身不会自动生成界面能力或完成注册。

适配器调用后端公开的读取或写入函数，通过 =Reader_backend= 向界面提供相应能力。公共撰写流程管理编辑和发送的生命周期，草稿与回执由各后端定义。

** Functor 注入依赖
协议实现可以通过 =Make (Transport : Http.S)= 接收传输模块。构建时为同一个协议实现选择传输方式。分页、错误和认证规则由后端处理。

分页结果包含内容及下一页游标。后端声明需要自动分页时，公共任务逐批持久化并更新列表；手动加载下一页也使用同一份游标。=C-c C-k= 可以取消当前列表加载，保留已收到的内容。

** 注册把能力接入运行中的程序
[[../src/reader_backend.ml][reader_backend.ml]] 目前提供两类注册：

| 注册对象           | 谁调用                       | 用途                                             |
|--------------------+------------------------------+--------------------------------------------------|
| 界面能力记录 =t=   | Emacs 主线程                 | 如何打开文章、显示按钮、删除、修改订阅和呈现结果 |
| =host= 与 =worker= | 主线程创建宿主，后台创建会话 | 如何获取列表、下载归档、执行后端任务             |

组配置通过 =backend= 选择后端，再由后端解释其组定位信息。适配器生成带后端前缀的持久键，站点、账户等后缀由后端解释。运行时按前缀选择对应的 worker，后端负责校验完整的键是否可用。=archive= 的 =refresh= 参数要求后端在归档更新时重新验证自己的缓存。

后端可以扩展 =Protocol.work= 和 =Protocol.payload=，也可以发布通用的 =Presentation= 数据。界面一侧的 =Value.t= 不应进入 worker。准备函数应在主线程读取配置，后台闭包只捕获普通 OCaml 数据。

=camulus_native.ml= 仍会列出要链接和安装的后端模块。这是构建与装配清单，不承担协议分派。当前扩展方式是加入 OCaml 模块并重新构建，不是运行时扫描第三方插件文件。

* 内容身份与回复树
组标识回答从哪里浏览，消息标识回答打开的是哪一条。后端负责这两种标识。需要区分多个服务实例时，后端应在组定位信息和消息标识中带上相应的实例信息。

[[../src/content.ml][Content.message]] 中，=id= 由后端提供，=parent_id= 和 =references= 描述回复和引用关系。持久存储用 =(backend_key, id)= 表达消息身份。后端应为同一条消息保留相同的键，使浏览组、订阅和收藏共享已读与收藏状态。

=content_state.ml= 的 =components= 根据父消息、引用关系及可用的原生讨论串 ID 构造连通分量，用于列表合并和归档覆盖判断。

=Reader_ui.render= 负责显示顺序：同一父节点下按来源时间排序，时间相同再按 ID 排序；缺失父节点的消息仍保留，循环关系不会导致无限遍历。界面用显式栈遍历已有消息，并不负责获取缺失回复；核心不再维护另一套未使用的排序实现。

渐进加载通过 =thread_batch= 表达：=messages= 是本批消息，=gaps= 描述未展开的部分，=complete= 表示后端是否完成该次讨论串读取。Emacs 界面合并批次并保持阅读锚点；只有后端知道远端是否还有内容。

* 一次请求如何完成
#+begin_src mermaid
sequenceDiagram
    participant U as Emacs 界面
    participant H as runtime_ui
    participant R as runtime 与 Eio
    participant B as 后端 worker
    participant S as 内容状态
    U->>H: 提交操作
    H->>R: Submit 包含 id work
    H-->>U: 返回请求编号
    R->>B: 执行任务
    B-->>R: 内容批次或操作结果
    R->>S: 按操作记录内容与状态
    R-->>H: Data 与 Finished 事件
    H-->>U: 在主线程交付结果
    U->>U: 检查视图有效性并更新 buffer
#+end_src

以组刷新为例，=Reader_ui.load_list= 提交 =Content_state.Refresh=。=runtime_ui.ml= 调用匹配的 worker，按其成员策略写入 =Content.page=，组窗口收到包含已读和收藏状态的列表行。订阅后台刷新只报告已写入的页及其下一页游标，打开的收件箱视图从本地查询自己的列表。=reader_ui.ml= 更新对应 buffer。远端分页合并到已有组成员，缺席条目仍保留。采用快照语义的 worker 在第一页重建成员，后续页追加。

后端的 =read= 能力返回专属任务描述，由公共运行时统一提交。当前实现先读取持久缓存，单篇文章命中后直接展示本地正文，讨论串先回放缓存，再执行后端读取。后端可以逐批返回正文和回复树，包含完整正文的批次会立即落盘。用户关闭或切换视图后，即使响应已经在路上，Emacs 界面仍需要判断它是否属于当前视图。“订阅同步与组浏览”一节规定了两种入口各自触发远端读取的时机。

收藏流程则先获取正文和所需资源，再提交归档和收藏关系。整个讨论串的归档需要后端报告完整；下载失败不能留下一个看似成功却内容不全的收藏。

* OCaml effects 与并发边界
** Eio 承担 effects 调度
[[../src/runtime.ml][Runtime.worker]] 在独立 OCaml domain 中运行 =Eio_posix.run=。一个 domain 可以运行多个 Eio fiber；fiber 在等待网络、定时器或 promise 时让出执行机会。后端可以保持顺序代码风格，同时允许其他任务继续执行。

当前 Camulus 没有另外定义一套自有的 =Effect.perform= 协议。应用操作用普通 OCaml 变体表示，异步等待和取消交给 Eio。增加一个后端不需要为每种 API 请求定义新的语言 effect。

同一个 Eio domain 上的多个 fiber 并不等于多个并行 CPU 执行线程。长时间纯计算或阻塞 C 调用仍可能拖住该 domain。每次启动的 worker 在第一次访问存储时打开 SQLite 连接，执行迁移并恢复待完成的清理。后续请求复用该连接，worker 退出时关闭它。SQLite 等阻塞工作通过 =Eio_unix.run_in_systhread= 执行，并通过 mutex 串行保护本地存储操作。

** Saturn 队列连接主线程与后台
SPSC 意为单生产者、单消费者。公共运行时的命令和事件各有一条队列。

| 队列 | 生产者 | 消费者 | 容量 |
|------+--------+--------+------|
| 命令 | Emacs 主线程 | Eio worker domain | 256 |
| 事件 | Eio worker domain | Emacs 主线程 | 512 |

两条队列都使用 =Saturn.Single_prod_single_cons_queue=。同一个 worker domain 上的多个 fiber 依次调用队列操作。若多个 domain 同时向一条队列写入，应采用对应的并发队列。

队列保存数据，管道负责唤醒。主线程提交命令后通知 worker；worker 发布事件后写入 Emacs 通知管道。Emacs process filter 在主线程消费结果，同时有 20ms 定时补偿。一次最多消费 64 个运行时事件，避免大量结果长时间占用界面事件循环。

命令队列满时，提交返回失败，调用者不能把操作当作已接受。事件队列满时，后台 fiber 等待并检查停止请求。停止使用独立原子标记，因此不要求先在已满队列中排入一条停止消息。

清理结束后，生命周期进入 =Stopped= 或 =Crashed=，提交和回收直接据此判断任务域是否结束，不再维护第二个完成标记。

** 取消和过期响应
=Protocol.request= 只包含 =id= 和 =work=。界面按请求 ID 取消已离开的列表或阅读任务，写入任务继续运行；运行时不再维护全局视图编号或任务归属分类。运行时最多容纳 32 个活动任务，等待发布终态的任务也计入限额。

取消通过 promise 和 =Eio.Fiber.first= 传播。Emacs 界面检查 buffer 内的请求 ID 和 token；存储刷新还检查入口版本，阻止较早发出的慢响应覆盖较新的列表快照。这几处检查分别保护任务生命周期、界面和持久状态，不能相互替代。

取消本地等待不表示远端写入已经撤销。当前 =voting.ml= 的 =Pending= 等状态是会话内乐观展示及结果协调，既不是持久离线队列，也不意味着等待下一轮定时同步才发送请求。通用离线写入重试尚未实现。

* 组、订阅和视图
=camulus-groups= 为浏览组设置显示名称。组注册控制浏览入口，订阅设置控制收件箱接收哪些更新。组目录展示已注册的浏览组。

界面在打开入口时读取并校验组配置。各后端通过 Customize 或远端接口提供订阅设置；公共层使用这些设置发现订阅源。

公共同步队列通过各后端的 =followed= 能力发现订阅，合并重复入口后异步刷新，最多同时刷新 4 个入口。后端可提供独立的订阅入口，若存在对应的已注册浏览组则复用其名称。首页保存同步进度和各订阅的分页游标。

** 订阅同步与组浏览
后端定义可用的浏览范围、订阅来源和内容读取能力。浏览 group 和订阅源可以引用相同的组标识，两种入口各有自己的同步语义。

| 入口   | 刷新                                                                                  | 打开条目                                     |
|--------+---------------------------------------------------------------------------------------+----------------------------------------------|
| Group  | 获取或更新浏览列表                                                                    | 展示已有本地内容，按需向后端加载正文和回复树 |
| 订阅源 | 发现新增或发生变化的内容，取回单篇正文，或加载整个讨论串的正文和完整回复树并写入 SQLite | 从收件箱读取已同步的本地内容                 |

通知、摘要和列表行用于识别待同步的内容。对于讨论串，订阅刷新会加载首帖正文以及后端当前可访问的各级回复，直到处理完分页和可展开的分支，并保存父子关系。刷新失败或取消时保留上次完整同步的内容，未同步完的讨论串可以在后续刷新重试。

同一内容从不同入口发现时，使用相同的 =(backend_key, id)=，共享正文、已读和收藏。收件箱按讨论串合并条目。已读在正文进入阅读窗口可见区域后更新。

*当前实现*：主页和组列表复用 =Content_state.Refresh=。后端随列表返回完整正文时会写入缓存，回复树主要通过打开条目读取。订阅刷新完整回复树并从收件箱直接读取 SQLite 中的副本，是上面的设计约定。

** 首页和视图

=camulus-home-views= 按声明顺序定义首页的视图。收件箱视图从公共同步结果读取，按后端、订阅、已读、收藏和时间筛选；浏览组和收藏夹视图复用各自的浏览界面。首页的未读和总数通过后台任务查询 SQLite。收件箱视图复用同一收件箱范围的移除记录，切换视图只改变呈现。

* 本地内容状态与归档
[[../src/content_state.ml][content_state.ml]] 使用 SQLite 保存内容状态，不负责决定订阅谁。数据库中的历史订阅表仅用于已有数据迁移，当前入口注册和后端订阅有各自的权威来源。

数据库从旧版升级时，在一个事务中把内容表的 =source= 列改为 =backend_key=。列值和消息 ID 保持原样，因此旧读状态、收藏关系和移除边界沿用既有键。

| 数据                          | 主要用途                                                                                       |
|-------------------------------+------------------------------------------------------------------------------------------------|
| =items= 与 =item_links=       | 内容身份、标题、来源时间、已读和回复关联                                                       |
| =entry_members=               | 某个已获取入口当前包含哪些内容                                                                 |
| =activities=                  | 同一内容的不同进展及发现序号                                                                   |
| =dismissals=                  | 列表已经移除到哪个进展                                                                         |
| =folders= 与 =favorites=      | 嵌套文件夹及收藏关系                                                                           |
| =archives= 与 =archive_files= | 正文缓存与归档资源 |
| =cached_threads=              | 已缓存讨论串的最近加载完整性                                                                     |

** 已读与移除相互独立
已读在正文进入阅读窗口可见区域后更新；后台取回正文不会自动标记已读。普通列表用灰色表示已读，用红色表示收藏，收藏夹内不重复使用收藏红色。

=d= 标记移除当前列表中已经处理的进展，=x= 执行标记。活动序号记录移除边界，来源时间负责显示排序；它们不是同一个时间概念。新的活动版本可以重新出现，重复拉取同一版本不应复活已移除的条目。统一时间线也会合并跨入口的相同活动，避免仅因新增一个入口而重复提醒。

后端可以通过 =delete= 能力提供来源专属的移除操作。收藏夹中的 =d= 只移除当前收藏关系。

Refile 在标记阶段为条目解析归档目的地。公共规则可选择收藏夹或导出文件，也可以把归档委托给后端的 =refile= 能力。Move 由用户手动选择，候选包含通用收藏夹和当前后端通过 =folder_move= 提供的目的地。收藏会保存本地副本，后端文件夹由该后端执行移动。=x= 执行当前视图中已解析的动作。

后端 =delete= 接收 =complete= 完成回调，排队成功不等于操作成功。公共列表先临时隐藏条目并保持阅读位置，每次列表刷新都过滤仍在处理的条目；成功后等源缓存更新再撤销过滤，失败或取消则恢复条目。该状态只存在于 Emacs 界面，不写入已读、收藏或 feed 移除记录，也不影响收藏夹。

** 正文缓存与收藏归档
收藏关系的键包含文件夹、来源、目标类型和目标 ID。同一篇文章可以加入多个文件夹，单独一楼和整个讨论串可分别出现。文件夹只显示直接归属的收藏，不汇总子文件夹内容。

归档保存正文及所需资源，资源的获取方式由后端决定。下载与数据库提交分开，提交使用事务。普通阅读也自动保存完整正文和附件元数据；=resources_complete= 区分仅有正文的缓存与已下载全部资源的归档，避免收藏命中普通缓存时跳过资源下载。从最后一个文件夹移除后，本地内容继续保留。

删除文件夹通过外键级联取消该文件夹及子文件夹中的关系，不删除已缓存正文或资源，也不会创造阻止远端再次获取的删除标记。

整个讨论串收藏的后续更新通过 =Refresh_archives= 重新获取并提交，按收藏目标去重；单篇收藏不重复下载。现有任务机制能够执行刷新，但并不代表已经具备所有后端的持续增量同步服务。

* 宿主与媒体
[[../src/host_stubs.c][host_stubs.c]] 处理通知管道的 SIGPIPE 保护。Ecaml 与 Eio 补丁负责适配 Emacs 的宿主生命周期和信号管理。需要创建外部进程的适配模块通过宿主接入 Emacs 的进程接口。

[[../src/reader_media.ml][reader_media.ml]] 按需加载 WebKit，管理阅读界面里的内联视频。Emacs 阅读界面负责正文、图片与媒体的呈现。

* 添加后端时需要改什么
1. 在 =src/backends/= 中建立来源目录，定义会话、组、分页与认证模型，实现需要的基础和可选能力。先确认内容 ID 和来源 ID 的稳定规则。
2. 使用外部库处理标准协议或格式；只保留来源特有的数据转换、HTML 选择和业务规则。网络请求应可取消，避免在 worker domain 中长期阻塞。
3. 注册 worker 的来源匹配、分页、归档与执行能力。可扩展 =Protocol.work=；普通内容结果也可使用共享呈现格式。
4. 为 Emacs 界面注册可用操作、可定制选项和时间线来源。协议模块不应调用 Ecaml。
5. 在 Dune 和 =camulus_native.ml= 的装配清单加入该适配模块。公共运行时不应新增后端名称分支。
6. 验证稳定身份、分页、错误与取消、订阅权威来源、归档，以及至少一条真实 Emacs 操作路径。

* 公共 HTTP 与凭据读取
[[../src/http.ml][http.ml]] 定义共享的请求、响应和 HTTP 方法，以及基于 ocurl multi 的 Eio 传输。公共传输负责 TLS、证书、连接与超时、取消及资源释放。后端选择允许的 URL、认证请求头、重定向策略和重试规则。

[[../src/credentials.ml][credentials.ml]] 提供凭据文件读取、可选的私有文件权限检查，以及原子替换保存。凭据读取在 Eio 系统线程中执行。[[../src/credentials_emacs.ml][credentials_emacs.ml]] 在 Emacs 主线程查询 =auth-source=，解析延迟凭据并返回普通 OCaml 字符串。

[[../src/firefox_cookies.ml][firefox_cookies.ml]] 提供只读的浏览器凭据来源，按配置的 profile 和 HTTPS 目标筛选未过期的 Cookie。后端负责授权协议、令牌刷新、账户选择和认证失效处理。

[[../src/html.ml][html.ml]] 基于 Lambda Soup 提供 HTML DOM、遍历、清理与媒体提取。后端选择正文和需要保留的结构。

* 当前限制
仍需持续注意：

- 界面边界有 =Yojson= 与 Lisp alist 的动态字段约定，OCaml 模块签名不能检查所有呈现字段。
- 归档刷新当前由任务触发；不同来源的增量更新能力、写入支持和编辑界面完整度仍不同。
- 新原生模块需要新的 Emacs 进程才能替换已经加载的模块，更新 Lisp 入口不足以替换 OCaml runtime。

* 撰写会话
[[../src/writing.ml][writing.ml]] 集中管理 Emacs 编辑 buffer 的生命周期：编辑版本、自动保存定时器、保存中的修改、关闭前保存及发送状态。后端用 =snapshot= 提供当前正文，用 =save= 和 =send= 提供异步完成回调。后端负责草稿存储和发送回执。可选的 composer 能力决定当前组的撰写动作和首页可选的目的地。

保存只确认提交时的 buffer 修改版本。若等待落盘期间又有编辑，旧保存结果不会清除新修改；会继续保存新版本。保存失败后停止自动重试，手动保存、关闭或发送可以重新尝试保存。关闭失败会保留编辑 buffer。

发送先持久保存草稿，并在等待保存时预留发送状态、将 buffer 设为只读，避免事件处理期间重复提交。后端确认发送成功后，即使本地清理未完成，也将会话置为已发送并阻止重发。失败时恢复编辑；不自动重试发送。不确定远端结果的持久防重仍由后端处理。
